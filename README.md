# AIドル

AIがコメントに返事をし、3Dアバター（VRM）が声と身振りで喋るバーチャルアイドルのシステムです。
今はフェーズ1（喋るアバター）まで実装しています。設計の全体像は設計書を参照してください。

```
管理画面 / (将来) YouTube・TikTok のコメント
        │ WebSocket
        ▼
server/  コメント選別 → Claude で返事を生成（文ごとにストリーミング）→ VOICEVOX で音声合成
        │ WebSocket（台詞・感情・動作タグ・音声・口の形のタイミング）
        ▼
avatar/  three-vrm で描画：待機モーション、身振り、表情、口パク、まばたき、視線
        │ ブラウザソース
        ▼
OBS → YouTube / TikTok
```

## 必要なもの

- Node.js 22 以上
- Claude API キー（[Anthropic Console](https://console.anthropic.com) で発行）
- [VOICEVOX](https://voicevox.hiroshiba.jp/)（任意。起動していなければ音声なし・口パクだけで動きます）
- VRM モデル（[VRoid Studio](https://vroid.com/studio) で作って VRM 1.0 で書き出し）

## はじめかた

```bash
npm install
cp .env.example .env          # ANTHROPIC_API_KEY を書き込む
cp ~/Downloads/your.vrm avatar/public/models/avatar.vrm
# VOICEVOX を起動しておく（任意）
npm run dev
```

- アバター: http://localhost:5173/
- 管理画面: http://localhost:5173/admin.html

管理画面からコメントを送ると、アバターが返事をします。「台詞をそのまま言わせる」では AI を通さずに喋らせられます。
赤い「すぐに止める」ボタンで、生成中の返事と再生待ちの台詞をすべて止めます。

## OBS での使い方

ソースに「ブラウザ」を追加し、次の URL を指定します。

| 用途 | URL | サイズ |
| --- | --- | --- |
| YouTube（横型） | `http://localhost:5173/?transparent=1` | 1920×1080 |
| TikTok（縦型） | `http://localhost:5173/?transparent=1&layout=vertical` | 1080×1920 |

「OBS で音声を制御する」にチェックを入れると、アバターの声が配信に乗ります。字幕を出したいときは `&subtitles=1` を付けます。

## 設定

- `config/character.json` … 名前・性格・話し方・守ること・NGワード。サーバーを再起動すると反映されます。
- `.env` … モデル（既定 `claude-opus-5-5`、思考の深さ `low`）、VOICEVOX の URL と話者 ID、ポート。

## 見た目（衣装・髪型）の自動選択

衣装と髪型の組み合わせを「Look」と呼び、1つの Look が VRM ファイル1つに対応します。VRoid Studio で衣装や髪型を変えたモデルをそれぞれ書き出し、`avatar/public/models/` に置いて `config/wardrobe.json` に登録してください。ファイルが無い Look は選ばれません。

AI スタイリスト（`server/src/stylist.ts`）が次の情報から Look を選び、着替えたときは本人が一言しゃべります。

- 管理画面で選んだシーン（雑談・歌枠・ゲームなど）と、日本時間の時間帯・季節
- Look ごとの視聴者の反応（表示時間あたりの「かわいい」「似合う」などの褒め言葉の数）
- 「着替えて」「ポニテ見たい」など見た目についてのコメント（まとめて判断し、前回の着替えから10分以上あけます）

用意の無い衣装を望まれたときは `data/wishlist.md` に書き残し、次に作る Look の参考にします。

## 完全自立に向けた自己改善

配信中、AI が自分の調整項目を1つずつ少しだけ変えて試し、視聴者の反応で残すか戻すかを決めます（`server/src/evolution/`）。

| 項目 | AI が変えるもの | 判断材料 |
|---|---|---|
| 性格・話し方 | プロフィール、口調、口癖、好きな話題、返事の長さ | 実際のやり取り、反応の良かった・悪かった返事 |
| 声 | VOICEVOX の話者（声色）、話す速さ・高さ・抑揚・音量・間 | 「声」「聞き取りにくい」などのコメント |
| 表情 | 感情ごとの表情の強さ、口の開き、まばたき、視線 | 撮影した顔の画像とコメント |
| 動き | 身振りの大きさ・速さ、待機中の揺れ、喋るときのうなずき | 動きについてのコメント |
| モデル | 目の色、輪郭線の太さ、影の付き方、リムライト | 撮影した画像とコメント |
| 衣装・髪型 | 新しい Look を企画して VRM を色替えで自動生成、着せる Look の選択、反応の悪い Look の引退 | 見た目への要望・褒め言葉 |

仕組み:

1. 実験は同時に1つだけ。項目ごとに間隔（クールダウン）をあけ、順番に試します。
2. AI の提案は一度に動かせる幅と有効範囲に収めてから、新しい版として保存・反映します。
3. 一定時間（項目ごとに45〜90分）使ったら、前の版と評価点（1時間あたりのコメント数＋褒め言葉×5−不満×10）を比べ、9割を下回れば自動で元の版に戻します。
4. 名前・一人称・守ること・NGワード（`config/character.json` の constitution 部分）は AI が変えられません。
5. 管理画面の「AIの自己改善」から、項目ごとに「今すぐ改善」「1つ前に戻す」「固定する」、全体の一時停止ができます。

新しい衣装・髪型の制作:

- 配信時間 `DESIGN_INTERVAL_MINUTES`（既定240分）ごとに、AI が要望と反応を見て新しい Look を企画し、既存の VRM の髪・服・靴・目の色を変えて `data/generated/` に書き出します（管理画面の ★ 付き）。60分以上使って反応が他の Look の中央値の6割を下回ったものは引退させ、作った Look は最大12個まで残します。
- 髪型や服の形そのものを変える必要がある案は、制作指示書として `data/creation-briefs.md` に書き出します。`MODEL_GENERATOR_CMD` に 3D 生成ツールを呼ぶコマンドを設定すると、指示書の JSON を標準入力で渡し、最後の行に出力された VRM のパスを新しい Look として自動で取り込みます。未設定なら、指示書を見て VRoid Studio などで作り、`config/wardrobe.json` に登録してください。

記録はすべて `data/` にあります。

- `evolution/changelog.md` … いつ・何を・なぜ変え、残したか戻したか
- `evolution/<項目>/history/v*.json` … 各版の値と理由
- `metrics.json` … 版ごとの使用時間・コメント数・褒め言葉・不満
- `wardrobe-generated.json`、`generated/*.vrm` … AI が作った Look
- `creation-briefs.md`、`wishlist.md` … 形の変更が必要な制作案、視聴者の要望

## YouTube との連携

YouTube のチャットに返事をし、視聴データを自己改善の評価に使います（`server/src/youtube.ts`）。

| 取れるもの | 使い道 |
|---|---|
| チャット | AI が返事をする。コメントの内容で各項目の褒め・不満を数える |
| スーパーチャット・スーパーステッカー・メンバー加入 | 他のコメントより先にお礼を言う。評価点に1件20点で加点 |
| 同時視聴者数（1分ごと） | 評価点を「視聴者100人・1時間あたりの反応」にし、視聴者が増えた版を加点・減った版を減点 |
| アーカイブの視聴維持率（配信の2日後、OAuth のみ） | 視聴者が離れた時間帯に使っていた版を記録し、AI が次の改善案を考える材料にする |

同時視聴者数があるときは、時間帯で視聴者数が違っても公平に比べられるよう、視聴者あたりで評価します。比べる2つの版の両方に視聴者数のデータがあるときだけこの方法を使い、ないときは従来どおりコメント数で比べます。

設定のしかた（どちらか）:

1. **OAuth（おすすめ）**: [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作り、「YouTube Data API v3」と「YouTube Analytics API」を有効にします。OAuth クライアント（デスクトップアプリ）を作って ID とシークレットを `.env` に入れ、`npm run youtube-auth -w server` を実行して、表示された URL から配信用のアカウントで許可します。出力された `YOUTUBE_REFRESH_TOKEN` を `.env` に追加すると、ライブを始めたときに自動でつながります。
2. **API キー**: 同じく API キーを作り、`YOUTUBE_API_KEY` と、配信の `YOUTUBE_VIDEO_ID`（または `YOUTUBE_CHANNEL_ID`）を設定します。視聴維持率は使えません。

API には1日 10,000 ユニットの上限があります。チャットの読み込みは1回5ユニットなので、10秒間隔（既定）でおよそ5時間半の配信ができます。長時間配信するときは `YOUTUBE_CHAT_POLL_MS` を大きくするか、Google に上限の引き上げを申請してください。

## AI の返事の形式

AI は各文の先頭に感情タグ、必要なら動作タグを付けて返します。例: `[joy][wave]たろうさん、こんばんは！`

| 種類 | タグ |
| --- | --- |
| 感情（表情） | `neutral` `joy` `fun` `angry` `sorrow` `surprised` |
| 動作 | `wave` `nod` `think` `bow` `cheer` `shake` |

動作は `avatar/src/motion.ts` の `GESTURES` に、ボーンの回転として定義しています。モデルによって見え方が変わるので、管理画面の「動作を試す」ボタンで確認しながら調整してください。
